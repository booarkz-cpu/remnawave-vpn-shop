# Remnawave VPN Shop 2.1.0 — понятная документация

## 1. Что это за система

Remnawave VPN Shop — интернет-магазин VPN поверх Remnawave. В состав входят:

- Backend API на FastAPI;
- PostgreSQL;
- Redis;
- рабочий процесс (worker) для фоновых задач;
- Telegram-бот;
- Telegram Mini App;
- административная панель;
- Caddy как внешний HTTPS-прокси;
- Alembic для миграций базы данных.

## 2. Что входит в 2.1.0

### Деньги и платежи
1. Идемпотентное создание платежей.
2. Защита webhook от повторной обработки и replay.
3. Immutable финансовый журнал платежей/возвратов.
4. Проверка суммы, валюты, заказа и статуса у провайдера.
5. Безопасные возвраты с защитой от повторного списания.
6. Reconciliation для неоднозначных операций.

### Надёжность
7. Очередь фоновых задач с блокировками, retry и backoff.
8. Идемпотентный provisioning в Remnawave.
9. Защита от одновременного продления, возврата и выдачи.
10. Liveness/readiness проверки.
11. Backup и проверка восстановления.
12. Безопасный update/rollback.

### Безопасность
13. CSRF, RBAC, MFA и управление сессиями.
14. SSRF-защита и DNS pinning для внешних адресов.
15. Безопасные заголовки и Trusted Host.
16. Audit log с request ID.
17. Антифрод и аварийный режим.
18. Секреты не попадают в release ZIP и backup-архивы приложения.

### Наблюдаемость и эксплуатация
19. Структурированные HTTP-логи, метрики, мониторинг провайдеров и рабочих процессов.
20. CI-проверки, проверка SHA-256, manifest и единая версия релиза.

## 3. Установка

1. Установите Docker Engine и Docker Compose.
2. Скопируйте `.env.example` в `.env`.
3. Задайте длинный `APP_SECRET` и `DB_PASSWORD`.
4. Укажите три домена: API, административная панель и Mini App.
5. Настройте Remnawave и необходимые платёжные провайдеры.
6. Запустите установщик `deploy/install-vps.sh` либо production build по инструкции `INSTALL.md`.
7. Выполните миграции: `alembic upgrade head`.
8. Проверьте `/health/live`, `/health/ready` и административную диагностику.

## 4. Обновление

Перед обновлением создаётся snapshot файлов и дамп PostgreSQL. При ошибке build/doctor запускается восстановление. Не удаляйте каталог `.rollback` до успешной проверки новой версии.

## 5. Платежи

Нормальный жизненный цикл:

`создан → ожидание → подтверждён → выдача → завершён`

Повторный webhook безопасен. Если внешний результат неизвестен, система не переключает провайдера автоматически и отправляет операцию в reconciliation.

## 6. Безопасность webhook

Каждый провайдер проверяется собственным способом. После проверки событие получает уникальный ключ `provider + event_id`. Уже обработанное событие не выдаёт подписку повторно.

## 7. Финансовый журнал

Таблица `financial_ledger` хранит неизменяемые события:

- `payment/credit` — подтверждённый входящий платёж;
- `refund/debit` — подтверждённый возврат.

Повторная запись блокируется уникальным `operation_key`.

## 8. Мониторинг

Используйте:

- `/health/live` — процесс работает;
- `/health/ready` — база и Redis доступны;
- `/health` — расширенный статус;
- `/metrics` — защищённые метрики;
- административные разделы «Мониторинг», «Рабочие процессы», «Очередь задач», «Провайдеры», «Аудит».

## 9. Восстановление

Регулярный backup считается пригодным только после успешной проверки checksum и restore-test. Production backup нельзя считать надёжным только по факту наличия файла.

## 10. Русский интерфейс

Пользовательские и административные тексты переведены на русский. Названия технических протоколов, API, Docker, PostgreSQL, Redis, Remnawave, WebAuthn и идентификаторов сохранены без перевода, чтобы ими можно было пользоваться в документации и журналах.

## 11. Staging

Staging использует отдельные credentials. Production credentials туда не передаются. Адреса внешних API проходят проверку публичности и DNS pinning. Redirects отключены в staging runner.

## 12. Перед включением production

- выполнить staging E2E;
- проверить тестовый webhook каждого используемого провайдера;
- проверить повторный webhook;
- проверить provisioning;
- проверить возврат;
- проверить backup restore;
- проверить rollback;
- убедиться, что все security checks CI прошли.
