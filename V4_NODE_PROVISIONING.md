# Node provisioning — production-safe flow

The shop deliberately does **not** call an undocumented Remnawave Node-creation API.
Current Remnawave documentation says to create the Node in `Nodes -> Management`,
copy the exact `docker-compose.yml` generated by the installed Panel, deploy it on
the VPS, and restrict `NODE_PORT` in the firewall to the Panel IP.

The provisioning endpoint accepts that official compose and performs only the VPS
installation step. SSH credentials are request-scoped and are not stored.

## Required SSH trust

Production provisioning also requires the VPS SSH host-key fingerprint in the
`ssh_host_key` field (`SHA256:...`). The backend rejects unknown host keys instead
of using Paramiko's insecure `AutoAddPolicy`.

## Flow

1. Create the Node in the installed Remnawave Panel.
2. Copy the official compose configuration.
3. Obtain the VPS SSH host-key fingerprint out-of-band.
4. In Admin, submit the host, SSH credentials, fingerprint and official compose.
5. The backend installs Docker if needed, writes `/opt/remnanode/docker-compose.yml`,
   pulls the image and starts the Node.
6. Restrict `NODE_PORT` to the Panel IP.

The exact Node compose remains controlled by the installed Remnawave version; the
shop never guesses undocumented API request bodies.
